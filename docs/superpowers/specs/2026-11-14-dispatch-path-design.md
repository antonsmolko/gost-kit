# Типизированный путь dispatch — #44

## Цель

Перенести namespace и имя действия в первый аргумент dispatch,
а данные передавать вторым аргументом:

```ts
dispatch('users/SetEmailAction', { email });
dispatch('users/LoadAction');
```

Владелец утвердил внутренний объект действия с отдельными namespace,
именем действия и payload:

```ts
{ scope: 'users', type: 'SetPageAction', payload: 2 }
```

Reducer читает данные из `action.payload`. Действие без данных объявляется
без поля payload. Примеры деклараций:

```ts
type UserAction =
  | { type: 'SetPageAction'; payload: number }
  | { type: 'SetSelectedAction'; payload: string[] }
  | { type: 'SetEmailAction'; payload: { email: string } }
  | { type: 'RefreshAction'; payload?: boolean }
  | { type: 'LoadAction' };
```

Payload может иметь любой тип, определённый конкретным действием.

## Контракт

- Namespace, имя действия и payload связаны типами; дополнительный ручной
  реестр не требуется.
- TypeScript подсказывает допустимые пути и проверяет соответствующий payload.
- Обязательный payload нельзя пропустить. Для действия без данных второй
  аргумент не нужен. Для необязательного payload второй аргумент необязателен;
  объект, состоящий только из необязательных полей, также допускает его пропуск.
- API callbacks и описания эффектов сохраняют объекты действий с новой формой
  данных. Новая форма применяется последовательно ко всему вызывающему коду.
- Порядок обновления state, ожидание эффектов и вложенных dispatch,
  обработка ошибок сохраняют текущую семантику.

## Предлагаемые решения для согласования

- Для root использовать явный путь `root/ActionType`.
- Заменить публичную объектную форму dispatch новой формой вызова.
- Ошибку формата пути сообщать через общий обработчик ошибок dispatch.
  Проверку существования действия во время выполнения отдельно согласовать:
  текущий reducer допускает отсутствие handler.

## Область изменения

Общий API находится в common/fc и предоставляется Svelte shell.
Обновить типы, исполнение dispatch, адаптеры эффектов, вызывающий код,
анализ dispatch в ESLint, примеры и документацию.

## Проверка

Проверить связь путей с payload, обязательность аргументов, маршрутизацию,
работу эффектов и существующую семантику ошибок и ожидания dispatch.

Предварительный эксперимент на TypeScript 5.9.3 прошёл для RootAction примера
и union из 2000 действий в 100 namespace. Окончательные типы должны повторно
пройти эту проверку.

Перед PR выполнить общий check, build и браузерные сценарии примера.
Подготовить changeset для затронутых публичных пакетов.
